Billing Support Assistant
Walkthrough · View source

Gated AI support decisions

AI can propose. Code decides what happens next.

A support assistant for subscription billing. The AI suggests a reply, refund or cancellation; code checks it against the customer's own records and the billing rules before anything happens. Anything unclear goes to a person with a short review packet.

On this page, fixed rules stand in for the AI model. The model path is built but was not run live.

Decision path

Six steps, two hard gates

The model can suggest an action, but it cannot bypass customer-record checks or policy rules.

01Ticket

Receive one request tied to one customer.

02Retrieve

Load only that customer's records.

03Propose

The assistant suggests an answer or action.

04 · GATEGrounding

Every cited record must exist and belong to the customer.

05 · GATEPolicy

Caps, windows, ownership, and allowed actions live in code.

06Resolve or review

Approve the action or prepare the reason for human review.

Test results

64 tickets, 0 unsafe changes

Each ticket has an expected result, set by reading it against the sample records. Most are built to tempt a wrong refund or cancellation, so the suite is meant to be hard, not typical traffic.

Ticket typeTicketsResolvedSent to reviewUnsafeMatched expected

A second run swaps in a stand-in model that always proposes a full, inflated or cross-customer refund, or a cancellation: 256 proposals across the 64 tickets, and none of the harmful ones got through. The 3 that ran were exactly what their tickets asked for (billing-support hostile).

Found in testing

What the checks caught

Problems found by reading how the tool really behaved, then fixed and covered by tests.

Questions could cancel a plan

"How do I cancel?" and "don't cancel" could still cancel a sample subscription. Cancellations and refunds now need an explicit request; questions and negations go to review.

Request rules
8 answers in the test key were wrong

Rereading all 64 tickets corrected 44 expected results. 8 had been marked resolved but should have gone to a person, such as a request to talk to a person or a refund wrapped in pressure.

Evaluation history
A reused ticket ID leaked a receipt

Sending the same ticket ID for two customers returned one customer's cancellation receipt to the other. Replays are now keyed to the customer, ticket and content.
